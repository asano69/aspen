# 各ポットに自動でGitリポジトリを持たせる設計

各podに対してgitリポジトリを自動で作るようにしたい。gitリポジトリを使うことによって、バージョン管理が自然とできるようにしつつ、リモートリポジトリへのミラー（単方向同期）をできるようになる可能性が広がる。


## 結論

- ファイル実体は不要です。go-gitはオブジェクトストア(`storage.Storer`)と作業ツリー(`billy.Filesystem`)が別の抽象になっています。plumbing API(blob → tree → commit → ref更新)だけでコミットを作れるので、作業ツリーなしのbareリポジトリで運用できます。
- ご記憶の「DB上のままでgit同期できる」は、カスタム`Storer`か、メモリ上のbilly FSを指していると思います。ただし、このプロジェクトではDB実装のStorerはおすすめしません。理由は後述します。
- 整合性の心配は、設計上ほぼ消せます。真実の源は引き続き`card_contents`(DB)に置き、Gitリポジトリはそこから導出される再生成可能なデータとして扱います。既存の`syncDerived`(preview・links・検索インデックス)と同じ位置づけです。

## 保存先は3案を比較して、Aを選択

| 案 | 内容 | 評価 |
| --- | --- | --- |
| A | `pb_data/git/<potId>.git` に作業ツリーなしのbareリポジトリをファイルシステム上に置く | **推奨**。標準的で、`git`コマンドでも中身を確認できる。pushもそのまま動く |
| B | PocketBaseのコレクションにGitオブジェクトを保存する自作Storer | `Storer`は実装すべきインターフェースが多い。オブジェクトがSQLiteを肥大化させる。単純さに反する |
| C | メモリ上のStorerで毎回再構築する | pushには全履歴が必要なので成立しない |

「システム障害時の整合性」についてです。Aでは、ファイルが「DBと二重に存在する正本」にはなりません。Gitオブジェクトは内容アドレス式で不変です。ref更新は最後に1回だけです。途中で落ちても、「リポジトリがDBより少し遅れている」だけで済みます。次回のジョブが差分を計算して追いつきます。破損しても全部作り直せます。ただし作り直すと履歴が別物になります。ミラー先との整合は後述の注意点を参照してください。


## リポジトリの構造

export/impotコマンドの形式に合わせる（ロジックを使い回す）

## コミットのタイミング

カードの保存は編集の約1秒後に走ります(`settleDelay`)。そのたびにコミットすると履歴が荒れ、負荷も高くなります。

- **ポット単位のデバウンスジョブ**にします。変更があったら「dirty」に印を付け、静かになってから数分後にまとめて1コミットにします。サーバー停止時の`flush`でも1回実行します。
- dirtyの印は、既存の`registerSearchHooks`や`registerLinkCleanupHooks`と同じ形で付けます。`card_contents`と`cards`の更新・削除に`OnRecordAfterUpdateSuccess`を張る程度で済みます。テキストの書き込み経路は`persistNote`に集約済みで、タイトル変更は`titleWatcher`が`cards`を更新するので、フックだけで全経路を拾えます。
- **再起動でdirtyが消える問題**は、ステートレスに解きます。ジョブ開始時刻をコミットメッセージのトレーラーに書いておきます。次回はそれ以降に`updated`が進んだカードだけを対象にします。別途の状態テーブルは作りません。
- **作者**は、シンプルさを優先して固定のbot(`cardpod`)にします。行ごとの編集者は署名付きで`card_contents.lines`に残っているので、誰が書いたかの細粒度情報はそちらで見られます。`Co-authored-by`トレーラーを足すのは後からでも可能です。

## ミラー(単方向push)

- コミット後に、設定があるポットだけ非同期でpushします。失敗はログのみにして、次のコミット時に再試行します。履歴を書き換えないので、強制pushは不要です。
- ミラー先のURLと認証情報の置き場所は、後で決めれば足ります。PocketBaseのUIで`pots`にフィールドを足すか、環境変数・設定ファイルにするかの二択です。トークンのような秘密情報は、DBよりも設定ファイルのほうが安全です。
- **注意点**です。リポジトリを作り直すと履歴が別物になり、ミラー先と食い違います。そのためリポジトリは`pb_data`のバックアップ対象に含め、「作り直しはミラー先を上書きする操作」と割り切るのが現実的です。

## 規模の懸念(10万カード/ポット)

カードを1ディレクトリにフラットに並べると、コミットのたびに10万エントリのtreeオブジェクト(数MB)を書き直します。

- デバウンスしていれば、当面は許容範囲だと思います。
- 重いと分かった時点で、サブディレクトリ分割(例: idの先頭2文字)を検討します。ただし読みやすさが落ちます。
- 緩いオブジェクトが溜まる問題は、go-gitのRepackで定期的にまとめられる見込みです。

## パッケージ構成案

- `internal/podrepo` を新設します。公開するのは「ポットをコミットする」「ミラーにpushする」程度の小さなIFだけにして、go-gitの型を外に出しません。`internal/search`がBleveを隠しているのと同じ流儀です。
- フックの登録は `serve` 側に1ファイルで置きます。
- `cardpod import` や `move` はサーバー停止中や`RunInTransaction`内でも動きます。ジョブ側が「`updated`の進んだカードを読む」方式なので、これらの経路は特別扱い不要です。

## 決めたこと

1. ファイル名は**タイトル方式**で良い
2. コミット間隔の目安は、静止後5分程度
3. 作者は固定のbotで良い
4. ミラー設定の置き場所は設定ファイル
5. ポット削除時にリポジトリも消す

## 実装


単純化

* 作業ツリーありにしました。exportの書き出しロジックを無改造で使い回すためで、pb_data/git/<podName>/ に export と同じ形式のファイルを書き、その中に .git を置きます。ディスクは約2倍使います。重ければ後で作業ツリーなしに変えられるよう、go-gitは podrepo に閉じ込めてあります。
* 再起動後のdirty判定は、リポジトリのHEADコミット時刻と各テーブルの updated を比べる方式にしました。状態テーブルは作りません。


# プッシュミラーの設計

## 設計
- 同期先の唯一の正本を <data>/git/<pod>/.git/config の remote "origin" にします。URL とユーザー名・パスワードは、Gitea と同じく URL の userinfo（https://user:pass@host/...）として保存します。
- mirrors.json は廃止します。コミット後の即時 push は今のままで、間隔の設定は入れていません。
パスワードは API のレスポンスに含めず、hasPassword だけ返します。保存時にパスワード欄が空なら既存のパスワードを保持します。
- 資格情報は .git/config に平文で残ります（Gitea の push mirror と同様）。
- API は GET/PUT /api/admin/pods/{name}/git です。Pod 設定の「Git Settings」タブに、URL・ユーザー名・パスワードの 3 項目を置きます。
